# Sirius API診断（Issue #2用）

製品とは別の一時的なChrome拡張です。Cookieや認証コードを取得せず、ログイン済みブラウザからの同一オリジンGETを確認します。
インストール直後に通信せず、「読み取り診断を実行」を押した時だけ動作します。

## 実行

1. リポジトリで `npm ci` と `npm run build:probe` を実行します。
2. Chromeの `chrome://extensions` で開発者モードを有効にし、「パッケージ化されていない拡張機能を読み込む」から **`probe-dist`** を選びます。製品用の `dist` とは別です。
3. 同じChromeでSiriusにログインし、ホームまたは科目の課題一覧を再読み込みします。
4. 右下の「Sirius API診断 v3（開発用）」で「読み取り診断を実行」を1回押します。旧表示の場合は拡張管理画面で診断拡張を再読み込みしてからページを開き直します。
5. 結果欄のJSONを確認します。診断後は拡張を削除できます。

科目一覧のGETを1回、表示中の課題一覧の科目を優先し、ナビゲーション内の科目と合わせて最大2科目の課題と小テストを各1回取得します。全科目を取得する診断ではありません。
さらにサイト一覧が1〜200件の有効なID配列なら、`_limit=1` で `_start=0,1,2` と初回件数の位置を読み取ります。重複する位置は取得結果を再利用します。最大9リクエストを順番に実行し、それぞれ15秒で打ち切ります。401/429で残りを中止し、リダイレクトは追いません。

## 出力する情報

- HTTP状態、応答の形式、固定された診断用エラー分類。
- 許可したプロパティ名と型、配列の空/非空、先頭要素の構造。
- 許可していないプロパティは名前も値も出さず、省略数だけを示します。任意のキーを持つprops等の中身は出しません。
- 課題一覧がある場合、科目と項目IDでAPIと照合し、公開日時・締切日時と一致/不一致/判定不能になった件数を示します。ID不明・重複は成功扱いにしません。画面で現在表示されている行だけが対象です。
- ページング: 取得件数、個人サイト形式（`~`始まり）の件数、IDの並びから観測した0始まり/1始まり候補、初回件数の位置に続きがあるかを示します。応答不足・重複ID・順序不一致は判定不能です。空の続きが観測されても、全アカウント・全科目の網羅性は保証しません。
- 最小サンプル: `sample.fixture` に必要なフィールドだけを取り出した匿名化応答を示します。サイトは先頭2件と取得対象サイトから最大4件、課題は先頭2件まで。空の小テスト配列も保持します。非空の小テストはフィールド未確認のためサンプル化しません。

課題名・科目名・氏名・ID・日時の実値、URL、本文、認証情報は出力しません。IDは診断1回の中で同じ架空IDへ置換し、日付は応答内の前後関係・同値を保つ架空の日付へ置換します。実際の時間間隔、秒以下、応答をまたぐ日付の一致は保持しません。公開状態の真偽値と許可した固定種別（`course` 等）は保持します。未知の値は置換し、日時が不正なサンプルは生成しません。ブラウザ内に永続保存せず、開発者サーバーへ送信しません。

日時の照合は `epochSecond` を秒、`nano` をナノ秒と解釈し、日本時間で分単位まで公式画面と比較する仮説検証です。`openTime` は公開日時、`dueTime` / `closeTime` / `dropDeadTime` は締切日時とそれぞれ比較します。同じ値のフィールド同士の意味や、秒以下の精度までは確定しません。

`sample.fixture` は**実応答からフィールドを選んだ匿名化サンプル**であり、元の完全な応答ではありません。未取得のフィールドや境界条件を確認したことにはなりません。`sourceCount`、`sampleCount`、`transformations` とともにレビューし、実機で取得したものだけを `tests/fixtures/` へ追加してください。人工テストの生成結果を実測fixtureとして扱わないでください。
画面の共有時は、診断欄以外に表示された個人情報を含めないでください。
