## 実行した画面検証

ローカルの正常シナリオ: 初回表示前のMock GETは0件。パネルを開くと6件、最大同時4件、架空の課題8件を表示。検索・科目/種別フィルター・完了チェック・閉じて再表示では6件のまま。模擬公式フォームの入力を維持し、閉じた後のフォーム操作も成功した。HTML風の課題名は文字列として表示され、img要素は0件だった。

部分失敗シナリオ: 成功課題4件と3範囲の警告。正常空は成功した範囲の空表示、未知JSONは「課題なしとは判断できません」。429は更新無効化と再試行時刻を表示。正常表示後の模擬401で課題・サイト・手元の完了印を消去。画面のアカウント識別リンクの変更でパネルが除去され、取得が中止された。

実機: 公式一覧5行について項目IDで照合し、タイトル5/5、期限の日本時間・分精度5/5一致、未対応行0。比較はページ内で行い、実タイトル・日時・識別子は保存しなかった。提出・受験・採点の操作は行っていない。詳細は [Sirius契約記録](sirius-contract.md)。

初回実機で標準fetchの呼び出し元を失う不具合を発見。`fetch.bind(globalThis)`で修正し、修正前に失敗する回帰テストを追加。プレビューのmockも呼び出し元を検証するようにして、同じ見落としを防いだ。

実機確認後、未知のフォーム内には挿入しないガード、チェックボックスの読み上げ名、パネル内キーイベントの伝播抑止、戻る/進むキャッシュ復帰時の空パネル再作成を追加した。自動・ローカルで検証し、これらの差分のSirius再確認は次回拡張再読み込み後に行う。

## 未実装・公開のブロッカー

1. 非空の小テスト、期限未設定値、利用者識別子のアカウント間分離はIssue #2で確認が必要。推測でフィールド・アカウントキーを確定しない。
2. 通常Chromeの実機・権限表示・200%ズーム・提出フォーム非干渉・別タブ設定同期はIssue #10の未完了条件。
3. ログインHTMLの確実な署名は未確認。未知HTMLを非対応として扱い、保守的に学習情報を消去する。リダイレクトは`redirect:error`で拒否し、ブラウザがネットワーク障害と区別しない場合は同じ通信エラー表示になる。
4. サイトの公開状態が不明なら除外件数を表示。最大10ページで打ち切った場合は取得範囲未確定。空ページまで取得しても履修科目全体の保証とはしない。
5. 所有者のライセンス選択、公開用メタデータ、ストア画像・アイコン、バージョン固定の配布ZIPはIssue #11で対応。ストア未提出、一般公開不可。

## 再検証手順

1. `npm run check && npm test && npm run build`。日時テストは必要に応じて `TZ=UTC node --test tests/api-model.test.ts` と `TZ=America/Los_Angeles node --test tests/api-model.test.ts` でも実行。
2. `npm run preview`。READMEの各シナリオで空/失敗を確認。プレビューは拡張権限や実際のstorageを検証しない。
3. 通常Chromeに `dist` を読み込み、ログイン済みの公式課題一覧でパネルを開く。公式表示との照合は件数だけを記録する。学習データ入りのスクリーンショット・HARを保存しない。
4. 保存内容や権限を人が確認し、環境・バージョンと残る条件をこの文書へ追記する。確認できない条件を合格にしない。
