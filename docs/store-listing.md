# Chrome Web Storeへの提出準備

Issue #11の提出用文案と作業手順です。実際の審査申請・公開は所有者が行います。公式要件は2026-10-08に確認しました。提出時はダッシュボードの最新の必須欄も確認してください。

## 掲載文案

名称: **Sirius 学習支援**

短い説明:

> 東京農工大学Siriusの課題を締切別に整理。拡張アイコンから一覧を開き、公式課題画面へ移動できます。非公式の学習支援ツールです。

詳しい説明:

> Siriusの課題を、期限超過・今日・今後7日などのまとまりで確認できる非公式のChrome拡張です。
>
> Siriusへログインした状態で、ツールバーのSアイコンを押すと一覧が開きます。課題名の検索、科目や種類の絞り込み、締切日時と残り時間の表示に対応しています。タイトルのリンクから公式課題画面を開けます。個別リンクが取得できない課題は、理由を表示して公式一覧へ案内します。
>
> 自分のリストの完了印は、Siriusの提出状態とは別です。正式な期限・提出状況を公式画面で確認してください。本拡張から提出、受験開始、採点は行いません。
>
> ブラウザの既存ログインセッションを使ってSiriusからデータを取得します。Cookieの値、パスワード、認証コードの読み取り・保存は行いません。学習情報を開発者のサーバー、広告、アクセス解析へ送信する処理はありません。取得に失敗した場合や未対応の応答がある場合は、その範囲を表示します。取得できた一覧が履修科目全体を網羅する保証はありません。
>
> 「読み取り専用」は現行コードの操作方針であり、Chromeの権限で書き込み操作を禁止する保証ではありません。詳細はプライバシーポリシーをご確認ください。
>
> 本拡張は東京農工大学、SiriusおよびSakaiの公式提供・承認を受けた製品ではありません。締切別の整理などの設計はComfortable PandAを参考にして、独自のコードと画像で実装しています。
>
> 不具合や要望: https://github.com/hoki621/sirius-chromeextention/issues
> 個人情報、Cookie、パスワード、生のAPI応答・HARは送らないでください。

小テストを非空データで取得できることが確認されるまでは、小テスト対応を掲載上の機能として宣伝しません。完了印の保存方式を変更したリリースでは、掲載文とプライバシーポリシーも同じ実装へ更新します。

## プライバシー欄の文案

単一目的:

> ログイン中の東京農工大学Siriusで、課題を整理して公式の閲覧先へ案内し、学生が期限を確認しやすくすること。

`storage` の用途:

> 種類フィルターと完了項目の表示設定をChromeの端末内ストレージへ保存し、対応版のタブ間で設定変更と保存データの削除を通知するためです。認証情報・学習情報の外部送信には使用しません。

対象ページへのアクセスの用途:

> `https://lms.sirius.tuat.ac.jp/portal` とその配下で課題一覧を表示し、ブラウザの既存セッションを使って同じSiriusのJSON APIを読み取るためです。その他のドメインにはcontent scriptを挿入しません。

リモートコード:

> 使用しません。実行するJavaScriptはすべてZIP内に含まれます。Siriusから取得するJSONはデータとして検証し、コードとして実行しません。

プライバシーポリシーURL候補:

`https://github.com/hoki621/sirius-chromeextention/blob/main/docs/privacy.md`

このURLは、最終版の文書をpushしてログインせず読めることを確認した後に登録します。学習情報は端末内でも取り扱うため、「外部送信しない」ことだけを理由にデータの取扱いを未申告にしません。データ分類のチェック欄は提出時の説明に従い、取得する課題名・期限・科目・識別子、保存設定を文書と照合して所有者が確定します。

## ライセンスの確認

実行時の外部依存はありません。ビルドに使う開発依存は以下です。名前・版・ライセンスは`package-lock.json`とインストール済みの各`package.json`を照合しました。

| 依存物 | ライセンス | 配布上の扱い |
| --- | --- | --- |
| TypeScript 7.0.2 | Apache-2.0 | 型検査用。処理系は拡張ZIPに同梱しない |
| esbuild 0.28.2 / `@esbuild/*` 0.28.2 | MIT | ビルド用。処理系・実行バイナリは同梱しない |
| `@types/node` 22.20.4 / `undici-types` 6.21.0 | MIT | 型定義。拡張ZIPには同梱しない |
| Comfortable PandA（設計参照） | Apache-2.0 | コード・CSS・素材の直接転載なし。参照箇所・コミットは`CREDITS.md` |
| 独自のSアイコン | 本プロジェクトの著作物 | 大学・上流のロゴを使用していない |

本プロジェクト自体のライセンスは所有者が選びます。軽量な再利用を望む場合はMIT、明示的な特許許諾も含めたい場合はApache-2.0が候補です。参照元がApache-2.0であることだけで独立実装のライセンスを自動的に決めません。選択後、著作権者を確認して`LICENSE`を追加し、必要な通知を配布ZIPへ含めます。将来上流コードや画像を直接取り込む際は、個別の通知・変更表示・NOTICE条件を再確認します。

## 所有者が確定する項目

- 開発者アカウントの登録・必要な登録料、メール確認、2段階認証。支払先・料金は登録画面で確認する。
- 公開者名、問い合わせ先、ダッシュボードが要求する住所・事業者等の情報。適用する公開範囲も確認する。
- プロジェクトのライセンスと著作権表示。
- 公開するプライバシーポリシーURL、データ取扱いの申告、配布地域・公開範囲。
- ログインが必要な機能を審査員が確認する方法。個人の大学アカウントやCookieを申請文書へ記載しない。架空データによる説明だけで審査アクセス条件を満たしたと扱わず、専用アカウント等が必要なら大学側の許可を含めて調整する。

これらの未確定項目、Issue #10の未確認条件、必須画像の不足がある間は、提出準備完了とは扱いません。

## 提出・更新手順

1. [受け入れ記録](acceptance.md)を確認し、実際に合格した条件と未確認条件を区別する。README・ポリシー・掲載文を実装と照合する。
2. `manifest.json`と`package.json`の版を一致させる。公開済み版への更新では必ず増やす。対象commitを確定し、`npm ci`、`npm run check`、`npm test`を実行する。
3. [パッケージ手順](packaging.md)に従ってZIPを生成する。`build.json`のcommit・version・SHA-256を確認し、ZIPから展開した拡張を新しいChromeプロファイルへ読み込む。
4. ダッシュボードへZIPをアップロードし、説明・画像・プライバシー・配布欄と審査用手順を入力する。未確定項目を解消してから所有者が審査へ提出する。
5. 承認後の公開操作も所有者が行う。ストアのURL、版、対象commit、公開日をリリース記録へ追記する。

Siriusの仕様変更時は、個人情報を含まないエラー分類と操作手順をIssueへ記録し、`sirius-contract.md`の上流仕様と照合します。生のAPI応答を公開せず、必要な形を架空fixtureで再現して回帰テストを追加し、上記の検証・更新手順を繰り返します。未取得範囲を「課題なし」と表示したり、未対応の小テストを推測で有効化したりしません。
